# Turning a hard CLI dependency into an optional accelerator

**Context:** `Alwe` (os/Alwe) wrapped the `cass` CLI to expose agent session
search as MCP tools. Every tool went dark whenever cass had a bad moment.
Solved 2026-07-24 under goal `be6423c3`.

## Problem

Two independent defects that presented as one "the search tool is broken":

1. **Exit codes collapsed.** The wrapper used `cmd.Output()` and folded every
   non-zero exit into a single error. cass exit 7 means *"lock or busy —
   retryable, back off"*: a scheduled `cass index` run holds the index lock for
   ~51s. Routine, expected contention surfaced to the caller as
   `cass search: exit status 7` and `health: false` — indistinguishable from an
   outage.
2. **Unit of repair ≠ unit of change.** cass keeps one global fingerprint
   (`content-v1:<convs>:<convs>:<msgs>`) over a corpus of transcripts that are
   natively local and append-only. A four-conversation drift therefore had the
   same remedy as total corpus loss: rebuild all ~9900 conversations. That
   rebuild deadlocked in a memory-budget standoff and was aborted by cass's own
   stall watchdog at exit 70, so the repair was deferred forever and re-attempted
   on every query.

## Solution

### 1. Honour the CLI's exit-code contract

Well-built CLIs publish one. cass ships
`cass capabilities --json | jq .exit_codes`, with `retryable: yes|no` and a
prescribed `agent_action` per code. Retry only what the contract marks
transient:

```go
var retryableCassExits = map[int]string{4: "network error", 7: "lock or busy"}

func (o *CassObserver) runCass(ctx context.Context, args ...string) ([]byte, error) {
	backoff := 250 * time.Millisecond
	for attempt := 1; ; attempt++ {
		out, err := exec.CommandContext(ctx, o.cassPath, args...).Output()
		if err == nil {
			return out, nil
		}
		if _, retryable := retryableCassExit(err); !retryable || attempt == 4 {
			// Return stdout too: the CLI may still have emitted a usable
			// verdict body alongside a non-zero exit.
			return out, annotateCassError(err, attempt)
		}
		select {
		case <-ctx.Done():
			return nil, ctx.Err()
		case <-time.After(backoff):
		}
		backoff *= 2
	}
}
```

Do **not** blanket-retry. Exit 1 on `cass health` is a *real answer*
("unhealthy"), and exit 3/5/6 need human action — retrying either loops on a
verdict or masks corruption.

### 2. Make the unit of repair match the unit of change

Key each source file on `(mtime, size)` and give each file's rows a contiguous
rowid range, so replacing one file is an indexed delete. No global fingerprint,
no full-rebuild concept:

```sql
CREATE TABLE files (
  path TEXT PRIMARY KEY, mtime_ms INTEGER, size INTEGER,
  messages INTEGER, rowid_lo INTEGER, rowid_hi INTEGER,
  indexed_at INTEGER, duration_ms INTEGER
);
CREATE VIRTUAL TABLE messages USING fts5(body, path UNINDEXED, line UNINDEXED,
                                         ts UNINDEXED, kind UNINDEXED);
-- replace one file:
DELETE FROM messages WHERE rowid BETWEEN :lo AND :hi;
```

Measured on ~9,600 transcripts / ~349k messages: **2m7s cold, 1.5s warm, 7–12ms
to repair one touched file** — versus the ~89-minute whole-corpus rebuild it
replaced. Emit a per-file actuals log so "only the changed file was touched" is
observable rather than asserted.

`modernc.org/sqlite` is pure Go (no cgo) and ships FTS5 — verify with a
throwaway `CREATE VIRTUAL TABLE ... USING fts5(...)` before building on it.

### 3. Fuse rankings; never sort raw scores across backends

Backend scores are not comparable — cass reports corpus-wide BM25 in the tens,
SQLite FTS5's inverted `rank` lands near zero. Sorting them in one list silently
buries every hit from the lower-scaled backend, which makes a "merge" decorative.
Use reciprocal rank fusion on positions:

```go
const rrfK = 60.0
fused[i] += 1.0 / (rrfK + float64(rank))   // rank is 1-based, per backend
```

A hit both backends found then outranks a single-backend hit, which is the
corroboration signal you actually want.

### 4. Verify identifiers mean the same thing before keying on them

The dedupe key was `(file_path, line_number)`. Both backends had a
`line_number`, so it looked sound — but cass's is not a file line number (it
reported lines 1 and 12 for a transcript whose first match is on line 14).
The key could therefore *never* collide, and the dedupe was structurally dead
while its test passed. Fix: resolve one backend's coordinates into the other's
space (locate the snippet text in the file), and document what cannot resolve
(synthetic `[Tool: …]` renderings are generated by cass and appear nowhere in
the source).

### 5. Separate "reachable" from "self-reports healthy"

cass calls itself unhealthy when its index is merely past a **300s** staleness
threshold, while searching perfectly well. On a 900s indexing cadence that is
most of every cycle. Report both:

```go
type CassHealth struct {
	Reachable bool     // the binary ran and produced a verdict
	Healthy   bool     // the backend's own judgement
	Errors    []string // e.g. ["index stale"]
}
```

Then a composed health check is healthy if *any* backend can answer, and relays
the backend's complaint as a notice rather than an outage. Align the threshold
you ask for with the real cadence — cass's own `status` surface already uses
1800s — after measuring the periodic job's cost. Here, shortening the schedule
to satisfy the 300s default would have held the index lock ~51s of every 300s: a
17% duty cycle traded for a cosmetic signal.

### 6. Report the running binary's build id in health

A patched binary sat on disk while long-lived MCP server processes kept serving
old code, with nothing distinguishing them:

```go
bi, _ := debug.ReadBuildInfo()   // vcs.revision + vcs.modified
```

Surface it in the health payload so a stale server is detectable instead of
invisible.

## Traps

- **A green test can hide an impossible scenario.** The dedupe fixture built
  cass's hit *using the local hit's own line number*, guaranteeing a collision
  the real system cannot produce. When a fixture constructs the very coupling it
  means to verify, derive each side independently or assert against real data.
- **Synthetic fixtures modelled backends as up/down only.** The stale-but-working
  state — the most common real state — had no fixture at all.
- **"Run it more often" is not free.** Measure the periodic job before shortening
  its period.
