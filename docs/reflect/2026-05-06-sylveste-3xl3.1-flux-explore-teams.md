# Reflection: flux-explore --teams sprint (sylveste-3xl3.1, F1-F6)

## What landed

`/interflux:flux-explore --teams` cross-domain debate-mode synthesis path. Default path
unchanged (byte-identical legacy frontmatter). When `--teams` is passed and Claude Code
agent-teams is enabled (`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`, claude >= 2.1.32), the
synthesis pass spawns a 6-teammate orchestrator-led debate (3 max-distance debaters +
author + questioner + lead) before writing the synthesis. Six features (F1-F6) implemented
across two repos:

* Plugin code → `interverse/interflux/` (commit `bb6bfcd` + `bd5d6be`): `teams_detect.sh`,
  `cluster_specs.py`, `team_synthesize.py` (prepare/finalize), `cost_capture.sh`,
  `benchmark_synthesis.py` + 4 test files. ~2,300 lines added.
* Probe verdicts → Sylveste monorepo (commit `5a53bdc3`): four `docs/research/flux-explore-teams-probes/*.md`
  files documenting mailbox-mesh / TaskCreated-pre-veto / lead-only-cost-attribution /
  ad-hoc-spawn verdicts.

Test count: 47 sprint tests pass (37 pytest + 10 bash detect). 8 pre-existing structural
test failures in the plugin repo remain unchanged from sprint start (`8bb50e0`).

## Lessons learned (worth carrying forward)

### 1. Probes-before-code paid off

The plan front-loaded four primitive probes (F1.1-F1.4) before any production code. Two
of them surfaced changes the plan needed:

* **TaskCompleted vs TaskCreated:** the plan specified a `TaskCompleted` hook for the
  round-cap belt-and-braces. The agent-teams docs are explicit that `TaskCompleted` only
  vetoes a *completion*; the hook that vetoes a future task *creation* is `TaskCreated`.
  The plan's intent was correct (use a hook to enforce a round cap), but the hook name
  was wrong. Caught before code, fixed in F4 implementation. If the plan had gone
  straight to coding, the hook would have been wired to the wrong event and silently
  failed at runtime.
* **Ad-hoc spawn supported:** the plan included a contingency to write transient
  `td-debate-{slug}-cluster-{N}.md` files in `.claude/agents/` if ad-hoc spawn turned
  out to be unsupported. The agent-teams docs make ad-hoc the *primary* spawn mechanism,
  so the contingency was removed from F3 scope. ~60 lines of dead code avoided.

**Carry-forward:** for any feature whose design rests on undocumented or recently-changed
external API behavior, schedule documentation-evidence probes BEFORE writing the design.
Cheaper than retrofitting code to a misunderstood primitive.

### 2. Code review found 4 silent-defect class issues that tests would have missed

The flux-drive-style review surfaced four issues the test suite couldn't catch because
they were *spec/contract* issues, not algorithmic ones:

* The frontmatter contract was *described* in flux-explore.md but not *imperatively
  written* — an agent reading the spec linearly would silently drop `teams_fallback`.
* `cost_capture.sh` skipped invalid session IDs without recording them anywhere — total
  was correct but attribution audits had hidden gaps.
* `team_synthesize.py` had a defensive-programming gap: status=complete but
  total_usd=None would render `synthesis_cost_usd: null`, violating the schema.
* `_audit_blind_r1` round-detection used substring matching, vulnerable to body text
  containing the substring "round 2".

All 4 fit the "silent failure" category — they would not have produced wrong outputs
under normal conditions but would have failed in subtle ways under edge conditions
(bad session IDs, malformed cost JSON, transcripts mentioning later rounds in body
text). Tests covered the algorithmic logic but not the contract surfaces.

**Carry-forward:** for code that interfaces with external systems via documented
contracts (frontmatter shape, JSON envelope schema, transcript format), add
contract-shape tests in addition to algorithmic-logic tests. Or: have a quality-gate
review look for contract drift after the algorithmic tests pass.

### 3. Sprint scope was right-sized; auto-tier-2 worked

Tier 2 auto-mode (auto-advance unless P0/P1 found, pause only on quality-gate FAIL)
worked as designed. F1 verdict review was auto-approved (no design-breaking findings),
and the quality-gates findings were all P2 — fixable in-line without pausing the sprint.
The 6-feature scope was achievable in a single execution session (~5 hours of work
elapsed, including reviews and fixes).

If F6.2 (live A/B benchmark requiring an actual agent-team run) had been in scope,
this would have been a 2-session sprint. Splitting it out as a follow-up bead
(sylveste-3xl3.1.19) was the right call — keeps the implementation sprint clean
while leaving the empirical signal as a separately-tracked next step.

## Surprises

* **Two-repo commit boundary.** The interflux plugin lives in its own git repo; only the
  probe docs and beads belong in the Sylveste monorepo. The first commit attempt failed
  because `interverse/` is gitignored at the monorepo level. Easy to recover from once
  spotted, but the failure mode (gitignore silently dropping all the code with no error
  signal until commit) is a footgun for future sprints touching plugin code.
* **The `git commit -- <paths>` flag-order trap.** First attempt at the Sylveste commit
  failed because the message was after the pathspec separator; git interpreted `-m` as a
  pathspec. Easy to fix; would not have happened with `git add` then `git commit -m` (no
  pathspec). The `feedback_explicit_pathspec_commits.md` rule is sound; the trap is in
  the syntax, not the rule.

## Open design questions for follow-up

The team config field name for member session IDs (`session_id` vs `agent_id` vs `id`) is
TBD — the docs say "agent ID" but don't show the JSON schema. `_extract_member_session_ids`
accepts all three to be robust, and the next live teams run will tell us which one is real.
Once known, simplify to one and add a contract test.

The `synthesis_quality_check_fail` fallback reason is documented in the schema but not
yet plumbed through the actual validation flow — `team_synthesize.py finalize` records
`synthesis_quality_check: pass | fail` directly into frontmatter rather than triggering
a fallback. Either tighten the schema (drop the unreachable enum value) or wire the
validation failure to actually trigger a Step 4b fallback. Slight design ambiguity worth
revisiting in F6.2.
