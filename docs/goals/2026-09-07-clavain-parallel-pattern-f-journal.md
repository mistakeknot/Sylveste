## Decisions

- **Reservations go through `ic coordination reserve`, not intermute.** interlock 0.2.20 reserves through intermute by default and through ic only when `INTERLOCK_RESERVE_BACKEND=ic`; on this Mac intermute is down, so the ic store is the live one. `reservation_db` and `reservation_scope` on the run file exist for a repo whose store or project name differs. Making the orchestrator intermute-first when intermute is up is a follow-up.
- **No rebase before the merge.** The condition says "a rebase attempt"; a rebase rewrites the validated commit, so the register's commit would no longer be the commit on main. The merge is fast-forward when possible, otherwise a merge commit, in completion order under one lock; a conflict parks the item with its worktree and branch intact. A rebase conflicts exactly when the merge does, so nothing is lost by dropping it.
- **An undeclared item reserves `**`.** Declared files come from `files:` on the item, else the plan's commit pathspec, else every backticked relative path in the plan, else the whole tree, so an undeclared item runs alone rather than unguarded. The dry run prints the derived list.
- **Register rows carry `pf <run>/<item>` at the head of the note**, so a row can be traced to its run and item without a new column in `pattern-f-verdict.sh`.
- **The interlock fix is based on origin/main (0.2.19) without a version bump.** The local `sweep/2026-09-02` lane holds an unpushed 0.2.20; the hook files are identical on both, and a bump here would collide. PR #11 carries the fix; publishing waits for that lane to land.
- **Sylveste-n8jf's mechanism was measured before the brief was written.** `claude -p --model sonnet "Which output style is active?"`: no flags → `explanatory`; `--settings '{"outputStyle":"default"}'` → still `explanatory` (the style is an enabled plugin, not a settings key); `--setting-sources project,local` → `Default`. The brief prescribes the flag that worked.

## What the first live runs taught (2026-09-07, 03:30 to 03:50 PDT)

Three defects surfaced in the first sequential attempts in a throwaway clone (runs c5abf25d, 91621bac, d9dd99e0), each fixed with a test before the next attempt:

- **`ic --db` must lie under ic's working directory.** The clone run pointed `reservation_db` at Sylveste's store from the clone's directory and ic refused it ("db path must be under current directory"). The orchestrator now runs ic from the store's root when `reservation_db` is set (test: `reservation_db` runs ic from the store root).
- **intercore's glob validator refuses a pattern over 50 tokens**, one token per character, so `tests/structural/test_orchestrate_fresh_output_size.py` (52) could not be reserved as itself. A long path is now broadened to its nearest short-enough parent with `/**`; over-reserving is safe. The demo plan's test file was shortened so the exact item does not hold `tests/structural/**` against the gauge item.
- **A failed reserve leaked its partial set.** On 91621bac the first path was reserved, the second refused, the RuntimeError path released nothing, and the next run's first item waited on `pf/91621bac/9hqr on scripts/orchestrate.py`, a lock from a dead run, exactly as designed and exactly wrong. The reserve now releases its partials before raising, and the item wrapper releases by owner on every exit. Also the stub store had to become atomic (a mutex around check-then-create) before the GATE fixture stopped flaking, which is a property the real store has and the stub did not.
- **Two threads on one main checkout race git's index lock.** A worktree add during a sibling's merge failed intermittently, so every git operation on the main checkout (worktree add, merge, worktree remove, branch delete) now runs under the run's one lock.
- **The codex validation seat cannot write uv's cache.** On d9dd99e0 the exact item's validator (validation-sol, a codex seat under workspace-write) replayed `cd tests && uv run pytest ...`, uv was denied `~/.cache/uv`, and the seat answered UNRUN as the contract says; on goal 60771535's run c44f9b33 the same seat had instead granted itself access and passed, so the outcome depended on the model's mood. `dispatch.sh` now passes `-c sandbox_workspace_write.writable_roots=[...]` for workspace-write codex seats, the user's uv cache by default (`CLAVAIN_CODEX_WRITABLE_ROOTS`, colon-separated; empty grants nothing), with a bats file.
