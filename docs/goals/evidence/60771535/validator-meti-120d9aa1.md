- **mtime freshness has a false-negative edge on coarse-granularity filesystems.** `os.path.getmtime(verdict_path) >= start` (scripts/orchestrate.py:1026) compares a sub-second wall-clock float against filesystem mtime. On 1s or 2s granularity mounts (HFS+, NFSv3, FAT, some FUSE) a sidecar written in the same second as `start` can truncate below it and be discarded as stale. Since the sidecar is unlinked pre-run, the clause only ever rejects, never wrongly accepts, so the failure mode is a fresh `STATUS: warn` or `error` silently becoming `pass` on a zero exit. APFS and ext4 have nanosecond mtimes, so it does not bite in current environments. The backdated-sidecar test asserts exactly this pass-through, which is per spec but worth knowing is the behaviour.
