## Findings

### no-condition-validation-step-any-tier
- **Severity:** P1
- **Where:** §What We're Building Pillar 1 (line 13); §Key Decisions item 6 (line 40)
- **What:** CONFIRMED. Line 13 states the constraint with precision: the completion condition must be judgeable by the Haiku evaluator "from surfaced output," bounded to ≤4000 chars, with "or stop after N turns" bounding where appropriate. But nowhere in Pillar 1's mechanics (research-first → single-question interviews → charter → melange-for-high-stakes) is there a described step that takes the drafted condition string and checks it against these three constraints — length, surfaced-output-only judgeability, boundedness — before the charter is ratified and `/goal` is minted. The doc treats "melange review of high-stakes charters" (line 13, line 36) as reviewing the charter as a whole (why/scope/acceptance-criteria), not as a mechanical linter pass over the condition string against the built-in's own evaluator contract.
- **Evidence:** Line 13's constraint list is the most operationally precise sentence in the whole doc — it names a specific evaluator (Haiku), a specific input restriction (surfaced output only, "never 'the feature is good'"), a specific length bound (≤4000 chars), and a conditional bounding pattern ("or stop after N turns"). Yet Key Decision 6 (line 40), which is the doc's only stated routing for ceremony/review depth, routes exclusively on `classify-complexity` stakes tier — it says nothing about routing on condition-well-formedness. A charter can be C1 (skip melange entirely, "one confirming question") and still produce a >4000-char condition, or one that references non-surfaced state ("the feature is good" in different words), and nothing in the described ritual catches it before `/goal` mint. This is a distinct failure mode from stakes-mis-scoping: even a correctly-scoped C5 charter with full melange could pass melange (which reviews strategic content: scope, acceptance criteria, adjacent-work verdicts) while the condition string itself is malformed for the Haiku evaluator, because melange's reviewed artifact is the charter's substance, not the condition string's syntactic/semantic fit to the built-in's judging contract.
- **Suggestion:** Add an explicit, tier-independent validation step between "charter drafted" and "`/goal` invocation mints the entity" — e.g., a cheap deterministic or Haiku-cost pre-check that the condition string is ≤4000 chars and references only artifacts the evaluator could plausibly see in surfaced output (bead-close evidence, exit codes, file diffs) — and specify what happens on failure (kick back to the interview loop, not silently truncate).

### c2-c3-melange-gap-is-a-terminal-gate-blind-spot
- **Severity:** P1
- **Where:** §Key Decisions item 6 (line 40); §Open Questions 'Terminal-gate shape' (line 45)
- **What:** The C1/C4-C5 melange routing in line 40 is stated as a *ritual-depth* decision, but from the terminal-gate lens it is also a *close-trigger-integrity* decision: whichever terminal-gate shape is chosen (two-layer ordered close, single-layer /goal-met, event-driven, or any newly surfaced lease/escrow shape), the thing that fires the kernel-gated sequence is the same unvalidated condition string from finding 1. For candidate (a), "/goal's Haiku evaluator owns the session loop" — so a malformed condition (too permissive, referencing unsurfaced state, or simply wrong) doesn't just produce a bad ritual outcome, it produces a bad *trigger for the entire terminal sequence* (verify-against-charter → reflect+compound → successor-proposal). C2/C3 goals — which the doc's own stakes language implies are the *bulk* of real goals (most work isn't trivial-C1 or full-epic-C4/C5) — get zero melange pass and, per finding 1, zero condition-validation pass either. This means the terminal-gate design's most common real-world input (a C2/C3 goal's condition string) is the least-checked artifact in the whole pipeline.
- **Evidence:** Line 40 names only C1 and C4/C5 explicitly; C2/C3 are structurally present (the metric is C1–C5) but never assigned a review depth in the text. Combined with finding 1's confirmed absence of any tier-independent linter step, a C2/C3 goal's condition string reaches `/goal` mint with no gate of any kind — not melange, not a cheap validity check. Since candidate (a)'s "verify-against-charter" step (line 45) presumably re-checks the *charter*, not the condition string's fitness for the Haiku evaluator, there is no described point in the entire lifecycle — formation, C2/C3 ceremony, or terminal verify — where condition well-formedness is confirmed for the majority tier.
- **Suggestion:** Decouple "condition-string validation" from "stakes-scaled ceremony depth" in the doc's language — the former should be a cheap, always-on check (independent of C1–C5 routing) and the latter should stay stakes-scaled as currently designed; state this split explicitly so C2/C3 isn't read as "no gate at all."

### melange-reviews-doc-not-fields
- **Severity:** P2
- **Where:** §Open Questions 'Charter storage shape' (line 48)
- **What:** The doc's own open question — "what the melange reviews (the doc) vs. what the kernel gates on (the fields)" — is itself an admission that even at C4/C5 with a full melange pass, the reviewed artifact (the charter doc) and the enforced artifact (the condition field the kernel/the built-in `/goal` actually gates on) may be two different objects with no described reconciliation step. If melange approves prose in the doc but the condition field was drafted separately (or diverges after doc edits post-review), the P1 gap in finding 1 persists even nominally past melange.
- **Evidence:** Line 48 poses this as an open question without resolution, and Pillar 1 (line 13) describes "twofold" terminal artifacts (entity + condition) without specifying a step that keeps them in sync or validates one against the other post-melange.
- **Suggestion:** When resolving the charter-storage open question, require that whatever melange reviews textually includes (or directly derives) the literal condition string that will be handed to `/goal`, not a paraphrase — otherwise finding 1's gap survives even a full melange pass.

### quality-gates-has-no-condition-check-slot
- **Severity:** P2
- **Where:** core/intercore/internal/phase/gate.go:20-30, 69-80; os/Clavain/commands/quality-gates.md:27
- **What:** intercore's actual gate-evaluation primitive (`GateCondition`/`GateEvidence`, with check types `artifact_exists`, `agents_complete`, `verdict_exists`, `verdict_clean`, `children_at_phase`, `upstreams_at_phase`, `budget_not_exceeded`, `runtime_evidence`) has no check type resembling "completion-condition validated against evaluator contract." quality-gates.md is confirmed 100% flux-drive today (doc's own line 27) with "zero melange awareness." So even if the redesign wires melange into review-gate routing per Key Decision 6, there is no existing machine-checkable slot to record "this charter's condition string was validated" as gate evidence — the fix in finding 1's suggestion needs a new check type, not just a routing change.
- **Evidence:** `gate.go:20-30` enumerates the closed set of check constants; none map to condition-string validation. `quality-gates.md:27` states flux-drive is the current sole reviewer with no melange path.
- **Suggestion:** When implementing finding 1's fix, add a new `GateCondition` check type (e.g. `CheckConditionValidated`) so the validation step produces inspectable evidence on the Goal entity, consistent with how every other gate in the system already records proof rather than a bare boolean.

## Verdict
CONFIRMED. The doc names the /goal evaluator's constraints with unusual precision (Haiku, surfaced-output-only, ≤4000 chars, N-turn bounding) but describes no step anywhere in the ritual — at any stakes tier, including C4/C5 melange — that checks a drafted condition string against those constraints before ratification. This is not merely an elicitation-quality gap: from the terminal-gate lens it means the trigger for the entire kernel-gated close sequence (candidate a) or any other terminal-gate shape is validated nowhere, and the doc's own C1/C4-C5-only routing (line 40) leaves the C2/C3 majority tier with zero gate of any kind on this artifact.
