# Round 3 / Probe 1 — fd-kernel-contract verdict

## Raw-finding verdicts

- **f-044 (stall detector gap): CONFIRMED, and worse than stated.** The kernel does have a stall detector — `internal/lifecycle` (timeout + token-velocity based, `lifecycle.go:225-247, 374-385`) — but it is dead code: zero production callers of `NewRegistry`/`CheckStalls` (only `lifecycle_test.go`). The serving path has no stall detection at all: `TimeoutSec` on a dispatch is only enforced while a caller is actively blocked in `ic dispatch wait --timeout` (`cmd/ic/dispatch.go:299` → `collect.go:135-144`); detached dispatches delegate enforcement to `dispatch.sh` (`spawn.go:171-172`) with no kernel-side backstop. `dispatch.Poll` returns a non-terminal dispatch with nil PID completely unchanged (`collect.go:37-39`), so those wedge forever. Nothing reaps dispatches stuck `spawned`/`running`. The highest-stakes stall window is auto-spawn: `ic run advance` fires the spawn handler synchronously, the handler swallows per-agent failures with a Warn log (`handler_spawn.go:46-51`), and advance discards the notifier error (`run_lifecycle.go:205`) — advance exits 0, the run sits in `executing` with no agent, no failure event, and no retry.

- **f-045 (replay gap): CONFIRMED with nuance.** Kernel-side replay exists (`ic run replay`, `internal/replay`) but is recovery-inert by construction: it refuses any run not `status=completed` (`run_replay.go:79-82`) — exactly the crashed/stalled runs you would need to recover — and `reexecute` mode is a hardcoded stub that always reports "currently disallowed by kernel policy" and exits 1 (`run_replay.go:115, 135-137`). External consumers get a cursor-based catch-up via `ic events tail --consumer`, which partially refutes the raw claim, but that path has its own bugs (below). Internal handlers (hooks, auto-spawn) have no execution cursor: they run in-process at advance time, so a crash between event insert and handler completion permanently loses the handler effect.

## Sweep summary

1. **portfolio/relay.go** — Cursor persistence is done right (events + cursor in one tx, `relay.go:210-226`), but `queryChildEvents` has **no run_id filter** (`relay.go:238-241`): it relays the child DB's entire `phase_events` history across all runs. A missing cursor replays full child history into the portfolio run's event stream — durable-record contamination. `mapChildEventType`'s default branch collapses all unknown child event types to `child_advanced` (`relay.go:87-98`). Relay runs only while the `ic portfolio relay` process lives (`cmd/ic/portfolio.go:192-208`); when it is down, the portfolio dispatch limit silently disables (`cmd/ic/dispatch.go:706-710` — "degrades gracefully", same inert-enforcement pattern as the settled budget finding).
2. **Audit chain** — Stronger than "write-only": the package is **never written and never verified** in production. `VerifyIntegrity` (`audit.go:214`) and `audit.New`/`Log` have no callers outside `audit_test.go`. Dead code + dead schema (`schema.sql:366`).
3. **MIGRATION.md** — Promised `ic compat status/check` exist (`main.go:832-913`). Landmine found: the kernel's own dispatch-stats path still reads `/tmp/clavain-dispatch-<pid>.json` (`collect.go:46`), so the Phase-3 cleanup the doc prescribes (`MIGRATION.md:77`) silently freezes live stats — and `ic compat status` will forever show dispatch as legacy because the kernel itself is the legacy writer. No landmine for the earlier-round fixes otherwise.
4. **Stall detector** — see f-044 verdict above.
5. **Replay** — see f-045 verdict above.
6. **Other internals** — two significant extras: (a) the **scheduler is a write-only queue**: `ic dispatch spawn --scheduled` / `ic scheduler submit` persist jobs and return success, but `scheduler.New`/`Start` have no production caller and there is no `ic scheduler run` subcommand; `Store.RecoverPending` (`store.go:110`) is also uncalled. (b) **`ic events tail` cursor is broken for coordination events**: the query hardcodes `sinceCoordinationID=0` (`events.go:126,128`) and the high-water-mark loop never tracks them, so `--follow` consumers are redelivered the same coordination events every 500ms poll; meanwhile the saved `interspect` cursor field is dead — loaded/saved but never used in any query.

## Top findings (highest leverage)

1. **Stall blindness is systemic, not one missing feature.** Four independent mechanisms (lifecycle detector, scheduler engine, scheduler crash recovery, audit chain) are fully implemented and tested but never wired into any serving path. The pattern suggests a landing-process gap: subsystems merge without the CLI wiring commit. Highest-leverage single fix: wire `dispatch.Poll`-based sweeping + lifecycle `CheckStalls` into a single `ic sweep` (or `ic doctor --fix`) command that marks dead-PID/nil-PID/over-TimeoutSec dispatches terminal and emits stall events — it converts all silent wedges into observable, contract-visible state.
2. **`ic events tail` coordination cursor hardcoded to 0** (`events.go:126,128`) — a one-argument bug that makes the only consumer catch-up mechanism spam duplicate coordination events every poll, and any consumer that treats events as commands will re-execute them. Fix is ~10 lines (track coordination in the high-water loop, pass the cursor, drop or wire the dead interspect field).

## REMEDIATION

REMEDIATION: (1) Add coordination cursor tracking to `cmd/ic/events.go` tail loop (pass stored value instead of literal 0 at lines 126/128, add `SourceCoordination` case to the high-water loop at 143-154, persist it in saveCursor); (2) add an `ic dispatch sweep` command that terminal-marks dispatches whose PID is dead or whose age exceeds TimeoutSec, and emits a stall event per affected run; (3) wire `scheduler.Store.RecoverPending` plus a `scheduler.New(...).Start()` runner behind `ic scheduler run`, or remove `--scheduled` from the dispatch contract until it exists; (4) scope `relay.go:238` queryChildEvents to the child run registered for the portfolio and map unknown event types to an explicit `child_event` passthrough instead of `child_advanced`; (5) either wire `audit.New`+`VerifyIntegrity` into `ic run` lifecycle and `ic doctor`, or delete the audit package; (6) surface auto-spawn failures as a dispatch/run event (`handler_spawn.go:46`) instead of a Warn-only log so stalls are detectable from the event stream.
