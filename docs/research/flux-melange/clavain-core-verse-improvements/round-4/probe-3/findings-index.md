## Area 2 — command-shaped coordination events × cursor 0

Coordination event taxonomy (internal/coordination/store.go): `.acquired` (cmd-shaped: "you hold pattern P — proceed with guarded work"), `.released` (cmd-shaped: "P is free — act now"), `.expired` (cmd-shaped: same as released), `.transferred` (informational: ownership bookkeeping), `.conflict` (informational: back off).

P1 | fd-firing-witness | core/intercore/cmd/ic/events.go:126,128,143-154,158-160 | The coordination cursor is hardcoded 0 in BOTH ListAllEvents and ListEvents calls, and the high-water-mark tracking + saveCursor cover phase/dispatch/discovery/review but never coordination — every poll of `ic events tail --consumer=<name>` re-delivers the FULL coordination history forever. For command-shaped events this is re-execution pressure: a reactor (the documented pattern: `ic events tail -f --consumer=<name>` driving actions) that is not idempotent and treats `coordination.released`/`.expired` as "pattern free — dispatch the queued edit" commits an irreversible effect on every poll interval: duplicate agent dispatches, duplicate token spend, duplicate edits to files that a new owner may have since reserved. The re-executed effect IS the irreversible commit; the witness's broken cursor is what arms it.
  intersection_justification: Contract parent: delivery semantics (exactly-once via cursor vs re-deliver-all) are consumer-visible contract, and one source silently has different semantics from its four siblings — invisible unless you diff the cursor handling column by column. Firing parent: re-stoking because the log position was lost — the firing record's own cursor is part of the firing machinery, and a zeroed cursor re-fires logged stokes. Contract alone files a cursor bug; firing alone files a re-execution hazard; only together do you see the re-delivered event is *command-shaped*, so the cursor bug commits irreversible acts rather than merely duplicating log lines.

P1 | fd-firing-witness | core/intercore/internal/coordination/store.go:82-85 vs 390-395 | The inline sweep inside Reserve expires locks with an explicit "does NOT emit events" tradeoff, while the standalone Sweep command DOES emit `.expired`. Same transition (lock→expired), two producer paths, opposite witness behavior — and the silent path runs inside *someone else's* Reserve transaction, the most common path in the system. Consequence for the record: a cursor-0 consumer sees `coordination.acquired` with no matching terminal event and concludes the lock is held; the DB says free. Two consumers reading two "contracts" of the same state make divergent irreversible decisions (one waits forever for a release event that will never come; one reserves and edits).
  intersection_justification: Contract parent: the EventFunc doc comment (store.go:29) lists `.expired` as a delivered type, but one producer path never delivers it — the type exists in the contract while its delivery is conditional on which internal path fired, an undocumented semantic. Firing parent: an unlogged stoke corrupts every later decision that trusts the record — here concretely: the wait-for-release decision. Contract alone sees a missing event; firing alone sees a missing log line; the intersection sees the *divergent-belief* outcome: the event stream and the state table become two contradictory witnesses and consumers have no rule for which to trust.

## Area 3 — audit chain as the ONE witness (compatibility verdict; details in verdict.md)

P1 | fd-firing-witness | core/intercore/internal/audit/audit.go:81-127,130-193 + VerifyIntegrity:214-280 | Wiring the audit chain to gate resolutions + dispatch transitions under the natural scoping (session_id = run_id) makes the witness cry tamper on legitimate firings. `New()` snapshots lastHash/sequenceNum into memory; two CLI processes producing transitions for the same run both read prev_hash=H and both write sequence n+1 — a chain fork.   intersection_justification: Contract parent: chain scoping and concurrency semantics are contract (per-session ordering, who may produce, fork detection) and are currently implicit — only contract analysis frames "the verifier cannot distinguish fork from tamper" as a contract defect. Firing parent: a witness that falsely declares the record corrupt is worse than no witness — it burns the record's credibility, and anagama discipline holds the firing log's authority as the asset that outlives any single firing. Neither alone: contract alone would spec multi-producer merging as a feature request; firing alone would just say "chain breaks, fix it." The emergent harm is the *trust erosion path* — spurious alarms retrain the humans who are the final consumer of the tamper signal.
