# Verdict — clavain-core-verse-improvements, round 0, distant tier

## fd-scriptorium-transmission

The stemmatic lens's core prediction held exactly: this corpus's failure mode is not wrong content but **untracked copying** — the ecosystem extracts skills into companion plugins and moves on, but the index layer (PHILOSOPHY.md, PRD.md, upstreams.json, fleet-registry.yaml) still describes the pre-extraction corpus, and nobody collated the copies against the exemplars. The single highest-leverage discovery is that the *live routing concordance itself* (~/.agents/skills/) is bound to a stale apocryphal fleet (~/.codex snapshot, including a deprecated flux-research skill), so even perfectly maintained canonical plugins in interverse are not the texts agents actually read. Top two opportunities: (1) repoint the ~/.agents/skills symlink layer at Sylveste/interverse and delete the deprecated flux-research copy — one mechanical fix that heals the whole reading path; (2) rebuild upstreams.json and fleet-registry.yaml from the actual corpus (39/65 dead fileMap targets; ghosts intercom/interbench; 43 cold-spot plugins) and add a structural test that collates index claims against the corpus the way test_prd.py already does for skill counts. Blind spots: the lens cannot judge whether any individual skill is *good* — a well-transmitted bad text passes every check — and it treats the ~/.codex snapshot as purely pathological when it may be a deliberate install cache. Coverage: full interverse enumeration (71 dirs, colophon table for all), Clavain index docs, upstreams.json, hooks/scripts marginalia spot-checks, deep-dives on interflux/interkasten/intersense/intermix/intertrust/intermonk; skipped per-skill content review of the ~40 plugins beyond doc-vs-actual sampling.

## fd-anagama-thermal-state

The firing isomorphism's sharpest yield: intercore has genuinely strong kiln bones — phase.Advance/Rollback are transactional-with-events, OCC is correctly propagated at the store layer, landed/receipt/audit give real causality and tamper evidence — but the failures cluster precisely where the kiln metaphor predicted, at **the seams where instrumentation is optional**: every CLI dispatch path wires a nil event recorder, every budget checker wires a nil recorder, the one stall-detector (internal/lifecycle) has zero importers, and the filesystem lock's 5-second staleness fuse means mutual exclusion simply does not exist for any firing longer than five seconds. The gate layer shows the same shape: the one true cone pack (runtime-evidence close gate, proof-hash + kernel hard-block) is excellent but opt-in by bead label, while the default paths (ship, Go enforce-gate) pass on the potter's confidence or fail open when the kernel is absent. Top two opportunities: (1) make the event recorder non-optional in dispatch.New and budget.New (or panic/fail-closed on nil) — one constructor change closes the largest class of silent stokes; (2) fix the lock break path to require PID-liveness failure plus staleness, or add heartbeat renewal — the current default voids mutual exclusion for every real run. Blind spots: the lens treats all unevented mutations as defects, but some (telemetry counters, replay-capture tolerance for unmigrated DBs) are deliberate engineering trade-offs a potter has no analog for; it also cannot weigh the performance cost of making every mutation transactional-with-events. Coverage: read state/event/runtrack/phase/lifecycle/dispatch/budget/cost/lock/replay/audit/receipt/landed/scheduler/observability/observation/sentinel plus cmd/ic wiring and the Clavain gate files (ship, land, quality-gates, lib-gates, lib-sprint, clavain-cli/phase.go, hooks.json, scripts/gates); skipped deep review of internal/agency, coordination beyond lock events, scoring, portfolio, and the contracts/overrides codegen.
