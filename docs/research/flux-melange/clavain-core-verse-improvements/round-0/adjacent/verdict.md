# Verdict — clavain-core-verse-improvements (round 0, adjacent/domain-expert tier)

## fd-ecosystem-consolidation

The ecosystem is more disciplined than its size suggests: the worst sprawl is concentrated in template-stamped artifacts (~50 gitleaks validators, ~58 bump shims, ~50 PHILOSOPHY doctrine blocks) where copies are still mostly identical — the drift clock is ticking but hasn't exploded. Genuine behavioral divergence is rarer but real: the two `lib-intercore.sh` copies silently disagree on failure semantics under an identical version stamp (P1), and Clavain's ship vs landing skills already issue different bead-sync commands. Top two opportunities: (1) make `core/intercore/lib-intercore.sh` the single distributed source of the ic wrapper via an installer instead of a "re-copy on major updates" comment, and (2) move the stamped-script fleet (validate-gitleaks-waivers, bump-version, check-versions) into `interverse/_shared` with symlinks or generation at publish time. Blind spots: did not diff all ~58 PHILOSOPHY.md/AGENTS.md pairs section-by-section (drift counts came from hash bucketing of the doctrine tail); did not compare intercore's Go `ic lock` internals against interlock's MCP server beyond entry points; ~45 interverse plugins outside the deep-dive list got README skims only. Covered: Clavain skills/commands/scripts/hooks in depth, intercore lib+cmd surface, interverse deep-dives on interflux, interlock, interdoc, interscribe, interpath, intership, intermux, interkasten, interpeer plus random sample (interline, interstat, intertree). Note: the brief's assumed Clavain-ship vs interverse-intership duplication does not exist — intership is a spinner-verb novelty plugin, not a ship workflow.

## fd-lifecycle-drift

The ecosystem has real versioning machinery — release-manifest.json with sha256s, a two-exit-code verifier, doctor subcommands on every install path, backup-first mutation in both installers — but the gates are mostly unwired: nothing runs the binary verifier at install/session time, and `ic` itself is resolved by bare PATH lookup with no version handshake, so the two most runtime-critical binaries (clavain-cli-go, ic) can silently lag the markdown that invokes them (two P1s). Version truth is messier than it looks: Clavain's CHANGELOG is 38 releases behind its own manifests, interlens's manifest disagrees with its changelog, and only 1 of ~70 interverse plugins keeps a changelog at all. Top two opportunities: (1) wire verify-release-binaries.sh (or a cheap `ic version`/buildinfo probe) into the SessionStart doctor hooks so stale binaries fail loudly instead of at first invocation, and (2) make bump-version/`ic publish` atomically land a CHANGELOG entry and collapse the duplicated plugin lists (agent-rig.json vs install-codex-interverse.sh fallback table) into one source. Blind spots: could not run installers or doctors (read-only probe); did not inspect the interagency-marketplace repo itself or Sylveste/install.sh (a fourth install path); did not verify whether `ic publish` enforces changelog entries for other plugins. Covered: full reads of install-codex.sh, install-kimi.sh, check-install-updates.sh, codex-bootstrap.sh, build-clavain-cli.sh, bump-version.sh; all ~70 interverse manifest version strings with nested-repo git recency; deep-dives on interflux, interlock, intership, interskill, interplug, interlens; intercore buildinfo.go, COMPATIBILITY.md, MIGRATION.md, lib-intercore.sh, .gitignore. Skipped: interverse hooks/scripts internals, upstream-sync-engine skill body, galiana/ and tests/ subtrees.

## fd-kernel-contract

Intercore has a genuinely better contract story than most CLI kernels — a generated schema registry, a semver'd COMPATIBILITY.md, cursor-based event catch-up, single-transaction gate+advance — but the enforcement layer is hollow: the parity test can't see the CLI, the flagship advance-result schema contradicts actual `--json` output, and the documented exit-code table is inverted relative to every command read. The worst finding is operational rather than structural: hand-run `sqlite3 DELETE FROM publish_state` against the live DB is the de-facto stuck-publish recovery (documented in handoffs, confirmed in beads) even though `ic publish unlock` now exists — consumers were never migrated (P0). Second-worst: `ic events tail --consumer` advances the cursor on stdout write, so a hook crash between read and processing silently drops the batch, with the at-most-once window and 24h cursor TTL in no contract doc (P1). Top two opportunities: (1) add a golden-output test that runs each `--json` command against a fixture DB and validates against the generated schemas — this one test would have caught the parity-test gap, the advance-result mismatch, and the inverted exit codes; (2) document and harden event delivery semantics (cursor-on-ack, or a stated at-most-once window plus TTL behavior) since interspect's evidence pipeline currently loses batches silently. Blind spots: did not read internal/portfolio/relay.go, internal/lock, internal/budget's reconcile path, or MIGRATION.md; skimmed rather than exhaustively read the 5,700-line lib-interspect.sh; dispatch auto-spawn / hook execution ordering not traced. Covered: full contracts/ tree, priority cmd/ic files (run_lifecycle, run_create, run_replay, gate, events, publish, portfolio), both lib-intercore.sh copies, the heavy Clavain consumer (lib-sprint.sh), and the six heaviest interverse consumers (interspect, interlab, intertrace, interphase, interpub, interstat). Skipped: bump-version.sh tails and research/prose docs beyond sampling.
