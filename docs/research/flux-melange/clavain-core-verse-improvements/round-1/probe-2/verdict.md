# probe-2 verdict — fd-kernel-contract (intercore lock + event internals)

All three prior findings CONFIRM, and each is worse in detail than the cluster summary suggested. The lock's stale-break path (`internal/lock/lock.go:329-351`) is timestamp-only with a 5-second default — `pidAlive` exists one file over and is wired into `Clean` but not into `tryBreakStale`, so the PID-liveness guarantee that AGENTS.md:80 and the vision doc (:377) advertise applies only to a manual janitor subcommand, not to the acquire path where dual-ownership actually happens; the sole production consumer, Clavain's `sprint_claim` (lib-sprint.sh:849), holds `sprint-claim` precisely to prevent a TOCTOU double-claim, which is exactly what a false break re-enables, and the bash fallback in lib-intercore.sh never breaks stale locks at all, so the same helper has two divergent semantics depending on PATH. The event-recorder picture is near-total: 15 of 16 `dispatch.New` sites across `cmd/ic` pass nil, so every dispatch transition driven through the documented `ic dispatch spawn/poll/wait/kill/retry` flow writes nothing to `dispatch_events` — only `ic run advance` records — and the one wired recorder fires after `tx.Commit()`, fire-and-forget with errors swallowed at Debug, flatly contradicting the "same transaction" doc comment at dispatch.go:237. The cursor finding also confirms: `ic events tail --consumer` persists the high-water mark per batch immediately after stdout encode (events.go:157-160), so interspect's consumer crashing between read and `_interspect_insert_evidence` drops the batch permanently, the 24h non-durable cursor TTL is in no contract document, and the vision doc's prune-protection guarantee is moot because no `ic events prune` command exists. Test coverage actively entrenches the lock bug — `TestStaleBreaking` pins timestamp-only breaking as correct — while the nil-recorder silence and cursor-advance behavior have no tests at all; targeted `go test` on lock/dispatch/event packages passes green on these pins. The scariest single confirmation is the lock: a safety mechanism whose docs claim liveness checking, whose only real consumer depends on it for race exclusion, and whose break condition (5s, no liveness) guarantees failure for any holder longer than a shell heartbeat.

## Fix shapes
- f-038: in `tryBreakStale`, after the timestamp check, require `meta.PID <= 0 || !pidAlive(meta.PID)` before breaking (reuse the exact guard `Clean` already runs at lock.go:270); flip `TestStaleBreaking` to use a dead PID and add a live-PID-no-break test; correct AGENTS.md/vision claims to match.
- f-039/40/41: extract the recorder construction from run_lifecycle.go:122-137 into a shared helper and wire it at all 16 `dispatch.New` sites; move the `AddDispatchEvent` insert inside `UpdateStatus`'s transaction (dispatch.go:239-297) so the "same transaction" comment becomes true, keeping only the notifier post-commit.
- f-018: add an explicit ack — `ic events ack --consumer=X --upto=N` that the consumer calls after processing, with tail no longer auto-saving — or, minimal-contract variant, document at-most-once-on-crash plus the 24h TTL in contracts/events/README.md and make `--durable` the default for registered consumers.

REMEDIATION: Amend the f-038 brief text to note the docs-versus-code inversion is bidirectional — the vision/AGENTS docs promise PID liveness that the break path lacks, so the fix must land in code AND docs, not code alone.
