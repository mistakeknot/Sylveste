# F1.1 — Mailbox Topology Probe

**Verdict: `mesh`** — teammates message each other directly without lead relay.

## Evidence

Documentation evidence is unambiguous; runtime experiment was not required (per plan F1.2 step 2 precedent: "If docs are explicit → record verdict from docs.").

### Direct quotes from `https://code.claude.com/docs/en/agent-teams`

> "Unlike subagents, which run within a single session and can only report back to the main agent, you can also interact with individual teammates directly without going through the lead."

> "Teammates work independently, each in its own context window, and **communicate directly with each other**." (emphasis added)

Diagram caption (Subagents vs Agent teams):

> "In agent teams, teammates share a task list, claim work, and **communicate directly with each other**."

Comparison table row:

| | Subagents | Agent teams |
| Communication | Report results back to the main agent only | **Teammates message each other directly** |

### "Context and communication" section

> **Teammate messaging**: send a message to one specific teammate by name. To reach everyone, send one message per recipient.

> The lead assigns every teammate a name when it spawns them, and **any teammate can message any other by that name**.

> **Automatic message delivery**: when teammates send messages, they're delivered automatically to recipients. The lead doesn't need to poll for updates.

## Implication for plan

F4.1 (blind R1) and F4.2 (Round 1.5 challenges) work as designed. The orchestrator-lead can gate Round-1 visibility by simply not broadcasting Round-1 posts to peers — but since teammates can also direct-message each other freely, the **blind-R1 enforcement is prompt-discipline, not topology-enforced**. This is a constraint to surface in F4 implementation: the orchestrator must explicitly instruct debaters to send Round-1 candidates *to the orchestrator alone*, not via direct broadcast to peers.

### Rider finding (orchestrator gating limit)

Mesh topology means the orchestrator cannot *prevent* a debater from messaging a peer directly. The blind-R1 contract relies on debater compliance with the spawn prompt instruction "Round 1: post your candidates to the lead only; do not message other debaters." If a debater violates this, the run is contaminated. **Mitigation:** the F4.5 transcript (which logs every mailbox event with sender + recipient(s)) makes violations detectable post-hoc. If detected, mark the run `synthesis_quality_check=fail` with reason `blind_r1_contamination`. No enforcement at primitive level is possible.

## Status

No design-breaking finding. F2-F6 cleared to proceed with the noted F4 prompt-discipline constraint.
