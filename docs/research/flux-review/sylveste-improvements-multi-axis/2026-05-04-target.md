# Sylveste Monorepo Improvement Review — Three Axes

## Context

Sylveste is a monorepo containing the open-source autonomous software development agency platform. It hosts ~63 Interverse plugins organized into 6 pillars across 3 layers, plus core infrastructure (`core/intercore`, `core/intermute`, `core/interbench`, `core/agent-rig`, `core/interband`). Subprojects under `interverse/` include slash command surfaces, agent runners, MCP servers, hook systems, and CLI tools.

Recent baseline:
- Cost-per-landable-change: $2.93 (785 sessions, 2026-03-18)
- Preamble trim shipped 2026-04-21 (`sylveste-ynh7`): −2,285 tok/session on target metrics
- Per-project Dolt for beads (v0.60.0, since 2026-03-15)
- CASS adopted as session intelligence backend (v0.2.0, ~10K sessions across 15 providers)

## Review Axes

This review surfaces concrete, actionable proposals across **three axes**. Each finding should include estimated savings (tokens, latency, UX friction) and difficulty (XS/S/M/L).

### Axis 1: Usability

Friction in user-facing workflows. Where do users get stuck, confused, or repeat themselves?

- **Slash commands** — discoverability, naming consistency, argument patterns, error messages, undo affordances
- **Agent invocation** — when does a user invoke wrong agent? When is delegation noisy?
- **CLI tools** — `bd`, `cass`, `clavain`, hooks — startup time, error clarity, consistent flags
- **Statusline** — information density, layout (currently 2-line; user has feedback memory on layout)
- **Hooks** — SessionStart noise (multiple hook reminders fire each turn), notification fatigue, configuration drift between settings.json and settings.local.json
- **Memory system** — MEMORY.md is over budget (132 lines / 120 budget); reload friction; staleness detection
- **Beads workflow** — bd push gate, bead-close ceremony, search/dedup before create, UX of `bd update --notes` vs `bd edit`

Look for ergonomic wins sitting on the floor — single-keystroke saves, default flags, inferred arguments, smarter prompting that removes a confirmation step without losing safety.

### Axis 2: Token Efficiency

Build on `sylveste-ynh7` (preamble trim, −2,285 tok/session). Where is the next layer?

- **Orchestration preamble bloat** — system prompts, MCP server instructions, deferred tools listing (~80 deferred tools listed at session start), skill listings (>100 skills), CLAUDE.md inclusions, MEMORY.md auto-load
- **Redundant context loading** — agents re-reading files already in caller's scope, `git status` repeated, `bd list` repeated, hook output duplicated across turns
- **Prompt structure** — verbose template scaffolding (e.g., flux-review skill itself is ~300 lines and gets copied into invoking turn), repeated frontmatter examples, "you are an expert" preambles
- **Subagent prompts** — when delegating, how much context is duplicated? Could references replace inlining?
- **Tool result truncation** — when do tool results bloat unnecessarily (full file reads when grep would suffice)?
- **Hook output** — SessionStart hooks emit ~50 lines of system reminders; how much is load-bearing per turn?
- **Activity loops** — `/loop`, `/sprint`, `/work` loops that re-orient on each tick

Target the next 2,000+ tok/session win. Find structures that compress without losing fidelity.

### Axis 3: Replace LLM Orchestration With Traditional ML / Deterministic Models

Where do we currently spend Claude/Codex tokens on classification/routing/ranking decisions that a cheap model would handle?

The **Intercept** project already does this for decision gates (Haiku → log → distill xgboost). Find the next 5 candidates. Examples to consider:

- **Agent triage** — `flux-engine` triages which agents to dispatch via Opus/Sonnet reasoning. Could embedding similarity + a small classifier do it?
- **Skill routing** — when a user asks a question, which skill should fire? Currently LLM-decided.
- **Model routing decisions** — `interspect`, `interrank` already partially do this. What else uses LLMs to decide model tier?
- **Bead deduplication** — `bd search` before `bd create` is currently the LLM's job. Could embedding-based fuzzy dedup automate it?
- **Memory recall relevance** — deciding which memory file is relevant for a question
- **Doc routing** — which doc to update, which artifact to regenerate
- **PR triage classification** — `/pr-triage` themes
- **Sprint phase classification** — which phase is the work in?
- **Hook activation decisions** — should this hook fire?
- **Voice fidelity scoring** — interfluence currently uses LLM compare; could be embedding similarity + style classifier

For each candidate: what's the input vector? What's the output? What's the LLM-cost being paid today vs. ML-cost (latency + retraining)? What's the precision/recall floor we need?

## Deliverable Shape

The review should produce **concrete proposals** — each with:

1. **Name + axis** (which of the three)
2. **Current state** (what code/flow does this today)
3. **Proposal** (what would change)
4. **Estimated savings** (tokens/turn, UX friction reduction, latency)
5. **Difficulty** (XS = config tweak, S = single PR, M = multi-PR, L = new infra)
6. **Risk** (what could go wrong)

Span semantic distance:
- **Adjacent**: Claude Code internals, Agent SDK patterns, MCP server hygiene, hooks lifecycle
- **Orthogonal**: Compiler/IDE design, build system caching, search engine ranking, IDE quick-actions
- **Distant**: Information theory, control theory, signal processing, queueing theory, biology
- **Esoteric**: Pre-modern crafts, non-Western knowledge systems, physical processes at non-human scales

Goal: actionable proposals with token/UX savings estimates and difficulty scores. Not abstract theory.
